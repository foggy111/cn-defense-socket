## 1. 选题背景

计算机网络课程要求学生理解 TCP/IP 协议栈、Socket 编程与应用层协议设计。单纯的“回显服务器”过于简单，难以体现软件工程完整流程。本选题在经典聊天室基础上增加：

1. **自定义二进制帧协议**（解决 TCP 粘包/半包）；
2. **文件分块传输与服务器落盘/点对点中继**；
3. **LLM 辅助诊断模块**（满足“必须使用大语言模型”的课程约束，同时服务答辩讲解）。

## 2. 与课程要求的对应

| 课程要求 | 本项目落实 |
|----------|------------|
| 与计算机网络相关 | TCP Socket、应用层协议、并发连接、字节序 |
| 软件工程真实代码 | C++17 服务端/客户端 + Python LLM 工具，可编译可运行 |
| 使用大语言模型 | `llm/diagnose.py` 调用 OpenAI 兼容 API，无密钥时 mock |
| 有一定难度与深度 | 帧协议、文件中继、多线程、设计说明书与答辩材料 |
| 四人分工清晰 | 甲服务器、乙客户端、丙文档、丁 LLM+答辩 |

## 3. 预期成果

- 可运行的 `server` / `client`（Linux / WSL，`g++` C++17）
- 协议文档、设计说明书、分工与答辩提纲
- 冒烟脚本与样例日志、LLM 诊断输出

## 4. 创新点简述

将**协议实现**与**智能运维诊断**结合：运行产生的日志可输入 LLM，自动归纳可能的 TCP/协议问题，便于答辩时展示“原理—实现—验证—分析”闭环。
