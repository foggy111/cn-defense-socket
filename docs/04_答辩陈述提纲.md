## 二、网络原理（约 3 分钟，可请丙补充）

1. TCP 面向连接、可靠、字节流 → 必须自己划分消息边界  
2. Socket API 与三次握手对应：`connect`/`accept`  
3. 本项目帧：`CN | ver | type | length(BE) | payload`  
4. 粘包/半包：先收齐头再收齐体  
5. 并发模型：thread-per-client + 互斥锁保护昵称表

## 可能提问与应答要点

| 问题 | 应答要点 |
|------|----------|
| 为何不用 UDP？ | 聊天与文件需要可靠有序；UDP 需自建重传 |
| 如何解决粘包？ | length-prefixed；recv_all 循环 |
| 为何要 htonl？ | 多机端序不同，长度字段必须网络序 |
| 文件很大怎么办？ | 分 CHUNK（32KiB）；限制单帧上限 |
| LLM 做了什么？ | 读日志+协议上下文→诊断；非替代协议实现 |
| 四人如何协作？ | 公共 `protocol.hpp`；丙出文档；接口先定再并行开发 |
